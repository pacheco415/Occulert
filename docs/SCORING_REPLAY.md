# Offline scoring replay

`src/scoring-core.js` contains the actual pure functions used by the live web
adapters: calibration samples/thresholds, sensitivity, six-frame EAR smoothing,
nod history, confidence/fatigue accumulation, eye metrics, continuity and alert
eligibility. DOM effects, delivery, cloud consent and clocks remain with their
existing owners. The live adapters retain separate wall-clock reads for score,
calibration, eye/distraction, nod detection and accepted alerts. Defaults,
thresholds, calibration duration and alert cooldown are unchanged.

The separate opt-in correction identifies exact `calibration-min=12` as
`calibrationMin` in both parsers and `detectorVersion`. It remains non-primary:
the released formula still runs with a 12-sample minimum. It now uses the same
local-only cloud gates as the other parked experiments. Empty, duplicate and
invalid values retain the one-sample released default. This metadata/cloud
boundary correction changes that opt-in route; it does not promote a default.

## Run a replay

Record while parked with `observer=1` or `detector=tasks`, then Stop and export
the local comparison JSON. Observer labels remain separate, independently
entered episodes. No label or accuracy number is generated by replay.

```sh
node benchmark/replay-scoring.mjs --trace local-trace.json --out fresh-replay
```

The output destination must not exist. Reusing an earlier run fails before
writing, so old alerts cannot remain beside a new unavailable manifest. Each
available variant gets `alerts.csv` (`session_id,at_ms`) and a diagnostic
`scoring.csv`. `replay-manifest.json` records capability, source/trace hashes,
the actual helper source, variant identity and missing phase-clock counts.
Unavailable variants have a reason and no alert CSV; unavailable never means
zero alerts.

| Directory | Decision policy |
| --- | --- |
| `released` | Released frame-count scoring and one-sample calibration |
| `fatigue-timing-elapsed` | `fatigue-timing=elapsed` |
| `perclos-time` | `perclos=time` |
| `calibration-min-12` | `calibration-min=12` |
| `noface-escalation-1` | `noface-escalation=1` |
| `distraction-confidence-stable` | `distraction-confidence=stable` |

The runner reuses the actual parked controller source for its existing variants,
not copied decision formulas. It recomputes smoothing/nods and continuity from
the same raw normalized EAR, nose and turn observations. Elapsed time, unknown
gaps and no-face evidence use their real models. Offline composition imports
the same live pure phases from `scoring-core.js` but stays outside the bundle.
Tasks remains measurement-only; there is no invented Tasks alert policy.

Use the existing adapter to prepare sessions/tracking and the observer's
independent episodes under the matching owned source revision:

```sh
node benchmark/parked-detection-trace.mjs --trace local-trace.json \
  --episodes independent-episodes.csv --participant pseudonym --split test \
  --out captured-inputs
node benchmark/run-event-benchmark.mjs --sessions captured-inputs/sessions.csv \
  --tracking captured-inputs/tracking.csv --episodes captured-inputs/episodes.csv \
  --alerts fresh-replay/perclos-time/alerts.csv --split test \
  --dataset scoring-replay-perclos-time --json perclos-time-results.json
```

Evaluate each policy separately. The sessions CSV retains capture provenance;
the replay manifest and explicit dataset name identify the counterfactual
decision policy. Do not concatenate variants into one detector/accuracy number.
Tracking and labels are still the recorded inputs, not inferred from replay.

## Trace version and capability boundary

The measurement/episode adapter accepts versions 1 and 2 while keeping its
exact owned-helper/runtime/model provenance checks. Run it with the matching
source revision, as before. Version 1 omits face/turn/nod, starting calibration
and phase clocks; those fields cannot be recovered from `legacyUsable`, which
also excludes calibration, turns, pitch and unpaired frames. Replay reports
that missing capability explicitly.

Version 2 adds a bounded `scoringReplay` record to deliberate local exports:

- An allowlisted initial scoring state, calibration/sensitivity settings and
  nonzero normalized epoch `1700000000000`. Zero timestamps remain sentinels,
  so the first eligible alert does not acquire a fictitious 12-second delay.
- At most 2,400 explicit raw/derived scoring observations with actual face
  presence, face absence versus invalid geometry, turn/nod/nose signals,
  monotonic observation time and normalized wall time.
- Named clock points for score, calibration, eye/distraction, nod sampling and
  decision, distraction eligibility and trigger. The live call placement stays
  unchanged. Wall-clock adjustments and monotonic frame ordering are distinct.
- At most 256 explicit recalibration controls, with current sensitivity and
  calibration deadline. Counterfactual fatigue/confidence are not overwritten
  by the recording policy's later state.

Only scalar scoring signals and bounded histories are exported. No image,
video, full landmarks, geographic coordinates, owner identity, credentials or cloud
payload is added. Exports stay in memory until deliberate download; the
existing small experiment summary remains the only local persisted summary.

Missing/invalid raw signals, unknown geometry, invalidated callbacks, truncated
prefixes or missing controls cannot establish complete replay state. Such
traces are unavailable or rejected, rather than filled with open-eye frames,
false booleans, default calibration or invented elapsed observations. Pixel/
pitch inputs cannot be converted back to normalized signals without original
landmarks and are explicitly unavailable in this replay contract.

Recorded named phase clocks are used where present. A decision phase absent
under the recording policy has no observed sub-frame timestamp; that
counterfactual phase uses the observation clock and increments its
`clockFallbacks` entry. The manifest states this timing limit. Exact sub-frame
onset is not claimed for those counterfactual decisions. This is offline
software evidence, not physical performance or independently labeled accuracy.

## Parity and cost

The independent oracle parses and executes an exact test-only copy of immutable
`driver-app.v97.js` function bodies and its actual caller eligibility and
trigger. Its SHA-256 must match the verified original constant documented in
`benchmark/fixtures/README.md`; retirement of the public URL/registry entry does
not affect it. The fixture stays excluded from deployment/offline inputs. It never
imports the new scoring implementation. Golden tests compare every scoring,
calibration and continuity field plus accepted alert timestamps at 3, 7 and
15 fps, across sensitivity levels and partial/fallback calibration. Boundary
cases cover eye thresholds, confidence, cooldown, microsleep/distraction and
face loss across the calibration deadline. The actual composed driver is
compared too, including an independently advancing 1 ms `Date.now` fixture.

Live version-2 export to released replay tests compare captured scoring and
decisions at all three rates with fixed and stepping wall clocks, with no
missing phase clocks. All six policies are also checked against actual live
helper/results paths on the same synthetic raw observations. These tests
generate no independent labels and authorize no promotion.

The released driver v101 measures 125,624 raw / 35,224 gzip / 29,318
Brotli bytes versus driver v100's 121,215 / 34,048 / 28,441: +4,409 / +1,176 /
+877. Its reviewed raw ceiling is 126,000. The optional helper measured 55,485
/ 15,839 / 14,148 versus v4's 51,370 / 14,845 / 13,255. The quoted static-install
audit sum is 373,884 bytes, within the unchanged 375,000 ceiling. The helper
remains outside default loading/install. Including the unchanged model/runtime assets,
selected install totals are 10,955,575 → 10,959,984 bytes with SIMD and
10,878,185 → 10,882,594 without SIMD (both +4,409; file counts unchanged).
Physical-device performance acceptance
is untested; these sizes and synthetic checks do not replace it.
