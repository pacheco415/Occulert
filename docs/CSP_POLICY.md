# External script and startup policy

HTML and generated controls use owned external scripts and fixed listeners. Both Vercel script policies permit owned scripts and the pinned WASM runtime, with no inline hash, nonce, `unsafe-inline` or general JavaScript eval grant. The audit rejects script-element and script-attribute overrides, duplicate directives, and inline/generated event handlers.

Connections allow the exact production project, `wbsynfcjpwlgdzioqpoa.supabase.co`, through HTTPS and WSS. The public configuration endpoint independently confirmed this host on October 4, 2026; no private key is part of this policy. Changing projects requires updating the public host constant, both connection policies, and their checks together. Current account pages load the owned pinned SDK. Previously published SDK loaders retain the CDN compatibility grant during their existing 14-day retention window; removing that grant requires the normal reference/retirement audit.

The early external startup guard has Subresource Integrity and joins the integrity-verified critical offline set. All driver-page scripts use ordered `defer` execution, with the guard first. Actual WebKit testing reproduced delayed execution of an asynchronous integrity-checked guard while a later driver response was held; ordered execution starts the guard deadline while the driver is still pending. A hung, missing, malformed or incomplete driver stays disabled. A missing or altered guard leaves HTML controls disabled and a plain parked reload link available. A held stylesheet may postpone WebKit first paint; the HTML remains disabled, and style completion after the deadline cannot enable monitoring. Readiness compares elapsed navigation time directly, so busy initialization cannot beat a queued timeout. A guard that arrives after the navigation's eight-second deadline fails terminally before a subsequent complete driver can enable controls. The frozen readiness handshake does not start a camera, detector, cloud session or microphone.

Release tooling copies the guard when a referenced driver filename changes, then recomputes the guard's HTML and worker integrity pins. Previously published files remain byte-for-byte unchanged. Worker network requests for pinned startup assets carry integrity, so a malformed network response cannot replace a valid offline guard. Browsers also check the HTML pin when loading from a cache.

Software validation covers browser loading order, timeouts, missing and altered files, offline startup, policy execution and immutable release tooling. Physical iPhone Safari/PWA behavior and actual detection quality remain separate acceptance checks. No alert threshold or detection behavior is changed by this release.
