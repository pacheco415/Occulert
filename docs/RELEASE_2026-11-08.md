## Health purpose strings

`native-app/app.json` declares both `NSHealthShareUsageDescription` and
`NSHealthUpdateUsageDescription`. The update string states that Occulert does
not write or modify Apple Health data. Two native verification cases passed on
this source's native tree:

- `scripts/test-dependency-compatibility.mjs`: "generated iOS HealthKit
  declarations include both Apple-required purpose strings", using the Expo
  CLI's introspected iOS configuration.
- `scripts/test-native-packaging.mjs`: "the installed camera plugin preserves
  generated iOS camera, audio and read-only Health declarations", which runs
  the actual config-plugin `infoPlist` mods and checks the HealthKit
  entitlement.

These cover the generated configuration, not a signed archive. At the build
step, inspect the archived phone Info.plist for both strings before relying on
this as a fix for ITMS-90683.

## Production gates

The ordinary production build requires these to stay off:

- Leave `EXPO_PUBLIC_EYE_BASELINE_EXPERIMENT`,
  `EXPO_PUBLIC_CAPTURE_LOAD_EXPERIMENT`, `EXPO_PUBLIC_EVENT_OUTBOX`,
  `EXPO_PUBLIC_UNANSWERED_ALERT_OBSERVATION` and
  `EXPO_PUBLIC_MOTION_ACTIVITY_OBSERVATION` unset or `0`. Each is enabled only
  by the value `1`.
- Leave `OCCULERT_MULTITASKING_CAMERA_EXPERIMENT` unset or `0` **before
  installation**. It controls a native source patch, so no runtime flag can
  toggle it.
- Leave `OCCULERT_SIMULATOR_TRACE` unset or `0`, and use the ordinary
  `production` profile. The `simulator-trace` profile cannot stand in for a
  TestFlight build.
- Keep server `OCCULERT_EVENT_IDEMPOTENCY_ENABLED` off. Server activation is a
  separate operational decision.

These describe reviewed source defaults, not an inspection of a live
environment.

At the separately authorized build step, inspect signing, quota, the remote
version counter and production environment before building the selected SHA.
Record the EAS build ID, assigned version/build, source, submission ID and
Apple processing state in private receipts. Inspect the generated phone and
Watch Info.plists: both Health purpose strings, the camera and Motion
disclosures, the absence of any location purpose string, entitlements, the
embedded Watch target, privacy manifests and `Podfile.lock`. Update the
[App Store privacy drafts](APP_STORE_PRIVACY.md) and
[review notes](APP_STORE_REVIEW.md) against that exact archive before
attesting them.
