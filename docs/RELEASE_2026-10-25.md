## Dated distribution receipts and build 57 rejection

The saved [distribution observation](status-observations.json) records build
**1.0.0 (56)** from `0d11ad22b66baab61ea9db6456bfaed837871537`.
EAS build `caeaa7c3-8b36-4d61-9d71-2766caef6921` finished October 3 at
23:44:38.728 UTC. The [October 4 release intent](RELEASE_2026-10-04.md)
records submission `5fa26508-b4d2-4d41-9c92-96694e9697b8` finishing at
23:45:24.885 UTC and the saved Apple states VALID, internal IN_BETA_TESTING,
external READY_FOR_BETA_SUBMISSION. These are dated observations, not a fresh
Apple availability, signing or quota check. No physical build-56 acceptance
is recorded. Earlier build-52 reports remain attached to that exact binary.

Apple subsequently rejected **1.0.0 (57)** with **ITMS-90683**, because
`NSHealthUpdateUsageDescription` was missing. The linked HealthKit library
contains APIs that trigger the purpose-string check even though Occulert
requests only read access. [#309](https://github.com/pacheco415/Occulert/pull/309)
restored the declaration in commit
`ee87033dae48ce12c82cc212dd3153d397624ad5`, merged as
`740a2d7b63d678995e4560b0e9562720a6a3dcd5`.

The restored text states that Occulert does not write or modify Apple Health
data and reads sleep and heart-rate variability only for private pre-drive
context. Both Health purpose strings must survive Expo config plugins into
the generated phone Info.plist. Native compatibility tests inspect generated
iOS declarations, including the Health entitlement and disabled background
delivery. Authorization remains read-only; no Health write permission is
added. See [native upgrade guidance](../native-app/UPGRADE_README.md).
This is a source fix; replacement-archive inspection and Apple's processing
result remain pending. No new build-57 source or submission receipt is inferred.
